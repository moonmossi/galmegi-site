# Metro GI 비교본

현재 `Levels/lvl_metro_block.tscn`의 정적 배경과 라이트를 새로 추출한 비교 씬이다. 캐릭터·게임 로직·기존 GI 노드는 제외한다. 원본 레벨 파일은 변경하지 않는다.

`verify_metro.gd` 실행 순서: 인자 없음(추출·재질 검사), `-- bake`(베이크), `-- render`(재질 보존 대조·재렌더), `-- hash`(리소스 ID 재발급 회귀).

측정 페이지 생성: `python addons/scene_lighting/custom_gi/analyze_metro.py` (Pillow 필요). `-- reuse`는 이번에 완료된 `17103539` 작업의 EXR을 재적용하는 진단 경로이며, 다른 씬 변경에는 사용하지 않는다.

실측 결과: Cycles 작업 77.509초, 적용용 재준비·저장 13.606초를 별도 실행에서 측정했다. 적용까지 한 번에 성공한 실행의 총시간은 아니다. 라이트맵 픽셀 데이터 9.55 MiB. 교대 GPU 측정 평균은 대합실 1.45 → 1.54ms, 하층 통로 1.46 → 1.55ms. 프레임 간 시간은 원본 약 2.0~3.2ms, 적용 약 2.7~4.0ms로 변동했다. GPU 증분 약 0.08~0.09ms는 이 배경 비교에 한정한다.

저장된 베이크 씬을 재열어 렌더했다. GI를 0으로 둔 재질 대조의 8비트 전체 화면 RMSE는 대합실 1.22, 하층 0.29였다. 원본의 그림자 샘플링 등 시간 변화도 포함한다. 공통 베이커 회귀는 23 checks / 0 failures이며, 리소스 재발급 동일성·실제 광도 편집 거부도 확인했다. 로드 시 기존 VFX 파싱 오류 및 종료 ObjectDB 경고가 있어 로그가 완전히 깨끗한 실행은 아니다.

빠른 비교 설정: 0.5m 텍셀, 32샘플, 자동 HDR 디노이즈, 프로브 간격 8m. 표면 라이트맵과 프로브의 런타임 적정 예산은 별도로 판단해야 한다. 이번 씬에는 움직이는 캐릭터가 없어 프로브 적용 품질을 검증하지 않는다.

Metro 전용 `metro_baker.gd`는 삼면 투영·버텍스 색상·AO·높이·거칠기 맵·발광 텍스처를 간접광 계산에서는 단순화한다. 투명 재질 또는 커스텀 셰이더가 포함된 메시 전체를 광 전달 계산에서 제외하지만 화면에는 원본으로 유지한다. 따라서 가림·빛샘·색 번짐이 실제 재질과 다를 수 있으며 제작용 정확한 베이크가 아니다. 일반 도크 베이커의 지원 범위를 완화하지 않는다.

화면에는 원본 StandardMaterial3D 복제본을 유지하고 `next_pass`로 GI를 더한다. 추가 드로우 비용이 있으므로 최종 제작용 통합 셰이더와 비용이 다르다. GI를 0으로 둔 `material_control` 화면을 원본과 비교한다. 측정 API 근거: [Godot RenderingServer](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html).

성능은 1280×720, TAA, 수직동기·FPS 제한 해제 상태에서 두 고정 카메라별 90프레임 준비 후 180프레임을 측정한다. `median_ms`는 프레임 간 벽시계 시간, `gpu_median_ms`는 뷰포트 GPU 시간이다. 메모리는 RenderingServer의 프로세스 전체 텍스처·버퍼 할당 수치로, 운영체제가 측정한 실제 VRAM 상주량은 아니다. 원본과 변환 리소스가 함께 메모리에 존재한다. 실제 게임 플레이 FPS로 해석하지 않는다.
